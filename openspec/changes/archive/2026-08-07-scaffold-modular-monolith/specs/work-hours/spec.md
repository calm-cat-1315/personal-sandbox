## Purpose

让使用者能够将一批日工时记录导入工作管理模块，并在前端查看这些记录。

## ADDED Requirements

### Requirement: 导入日工时记录

系统必须接受来自单个上传文件的日工时记录导入，并将导入结果持久化以便后续检索。

#### Scenario: 导入成功

- **WHEN** 用户通过导入入口上传合法的日工时导入文件
- **THEN** 系统应保存其中的日工时记录
- **AND** 系统应反馈导入已成功完成

#### Scenario: 拒绝非法导入内容

- **WHEN** 用户上传的文件不是合法的日工时导入文件
- **THEN** 系统应拒绝该次导入
- **AND** 不得将部分成功表现为「导入已完成」

### Requirement: 通过 API 列出已导入的日工时记录

系统必须提供 HTTP API，返回已持久化的日工时记录，供客户端展示。

#### Scenario: 导入后列出记录

- **WHEN** 已有一条或多条日工时记录被导入
- **AND** 客户端请求日工时列表 API
- **THEN** 响应应包含这些已导入记录，并具备足以识别每日条目及其工时的字段

#### Scenario: 尚未导入时返回空列表

- **WHEN** 尚未导入任何日工时记录
- **AND** 客户端请求日工时列表 API
- **THEN** 响应应表示空集合且不报错

### Requirement: 前端展示已导入的日工时记录

前端必须提供工作管理视图，展示从后端获取的已导入日工时记录。

#### Scenario: 展示已导入记录

- **WHEN** 后端已存在日工时记录
- **AND** 用户打开工作管理视图
- **THEN** 视图应以可读的列表或表格展示这些记录

#### Scenario: 从前端发起导入

- **WHEN** 用户使用前端导入控件上传合法的日工时文件
- **THEN** 前端应将文件提交到后端导入 API
- **AND** 成功后展示列表应刷新并包含新导入的记录
